# agent_office 🐒

Локальный «обезьяний офис» агентов Claude Code: задачи → агент в своём git worktree →
diff на ревью → мердж в main. Без облаков и аккаунтов, только твоя подписка.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.main            # http://127.0.0.1:8600
AO_FAKE=1 .venv/bin/python -m app.main  # имитация агентов — смотреть интерфейс без логина
```

Нужен CLI `claude` (`~/.local/bin/claude`) и вход в аккаунт: `claude` → `/login`.

## Как это устроено

```
app/core/tasks.py     задачи в workspace/tasks.json: todo → running → review → done
app/core/worktree.py  ветка agent/<id> + git worktree на задачу; merge --no-ff после апрува
app/core/runner.py    ClaudeRunner: claude -p --output-format stream-json; FakeRunner для тестов
app/core/office.py    очередь по агентам (один агент — одна задача), ревью, reject/retry
app/core/planner.py   миссия -> план подзадач (claude в режиме только чтение, строгий JSON)
app/core/roster.py    состав офиса: workspace/roster.json (имя, роль, модель, стол)
app/core/memory.py    workspace/agents/<имя>/MEMORY.md — дописывается после каждой задачи
app/telegram.py       Telegram-мост: задачи из чата, карточки на ревью с кнопками
app/main.py           FastAPI: REST + WebSocket событий; ui/ — пиксельный офис (floor.js), лента, канбан, ревью
sandbox/              учебный git-репозиторий для экспериментов
```

Поводок: агент правит файлы только в своём worktree, из Bash ему разрешены
чтение, тесты и git-диагностика (`runner.ALLOWED_TOOLS`). В main попадает только
то, что ты одобрил на ревью, глядя на diff.

## Миссии

«🎯 Миссия» — одна большая цель. Майкл читает репозиторий (без правок) и отвечает
JSON-планом: 2–6 подзадач, исполнитель, зависимости. Подзадачи создаются как
обычные задачи; зависимая стартует, только когда её зависимости одобрены и влиты
в main — так она видит результат предыдущих. Конфликт при мердже переводит задачу
в «ошибка» с подсказкой «Повторить»: агент переделает поверх свежего main.

## Приложение (.app)

`scripts/build_app.sh` собирает `~/Applications/agent_office.app` — нативное окно
(pywebview / WKWebView) с сервером внутри процесса, своя иконка в Dock. Лаунчер
запускает `app.desktop` из папки проекта, поэтому обновления кода подхватываются
без пересборки; пересобирать нужно только при переносе проекта. Логи —
`workspace/logs/desktop.log`. Если порт 8600 занят, окно берёт свободный.

## Пиксельный офис

`ui/floor.js` рисует мир 512×288 «пикселей» в offscreen-canvas и масштабирует
целым числом без сглаживания. Спрайты — строки-сетки в коде: человечки со своей
причёской и цветом рубашки (цвет агента), стол со стулом, монитором (мигает при
работе) и доской «ПЛАН» при планировании. Люди ходят: новая задача — к лотку
«задачи» за конвертом и обратно; готово — с конвертом к лотку «ревью»; в работе —
печатают; на ревью — поднимают документ; одобрено — на стол кладётся документ с
галочкой. В офисе постоянно живут два кота (рыжий и серый) — гуляют, иногда
ложатся отдохнуть и мяукают в облачке-комиксе. Шрифт Pixelify Sans (есть кириллица).

## Темы оформления

Весь интерфейс — в пиксельном стиле (квадратные углы, ступенчатые тени, Pixelify
Sans, сетка на фоне). Три темы переключаются в шапке и запоминаются в браузере:
**Аркада** (неон, розовый/жёлтый), **Game Boy** (4 зелёных тона), **Кибер**
(тёмно-синий, голубой/розовый неон). Палитра пола офиса меняется вместе с темой
(`THEMES` в `ui/app.js`, `Floor.setTheme`).

## Telegram-мост

В `.env`: `AO_TG_TOKEN` (бот от BotFather) и `AO_TG_ADMINS` (tg_id через запятую —
только им бот отвечает; остальным показывает их id и молчит). Мост живёт внутри
процесса сервера и работает с тем же Office.

- любой текст → задача Майклу в текущий репозиторий; `@dwight текст` — другому агенту
- `/repo` — выбрать репозиторий, `/mission текст` — миссия, `/status` — доска, `/diff <id>`
- готовая задача приходит карточкой с кнопками **Одобрить / Отклонить / Diff**; отклонение
  спрашивает причину, она уходит агенту при «Повторить».

## Хук после мерджа

В `workspace/repos.json` репозиторий можно задать объектом:
`{"path": "…/Velo_bot", "after_merge": "./scripts/restart.sh"}`. После «Одобрить»
команда выполняется в каталоге репозитория (например, перезапуск бота на новом
коде), результат уходит в ленту и в Telegram.
