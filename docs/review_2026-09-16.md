# Ревью cyber_office — 16 сентября 2026

Объём: ~2.8k строк Python, ~3.1k строк фронта (JS/CSS/HTML), 262 теста, 99 коммитов за неделю.
Через офис прошло 104 задачи и 16 миссий (3517 ходов агентов, ≈$119 по счётчику API — в подписку).

## Оценка
Проект рабочий и приносит пользу каждый день: на нём построены Velo_bot (298 тестов), test_hub, net_doctor и сам офис.
Архитектурно верно: чистая логика отделена от DOM и тестируется в node, Runner/Planner подменяются фейками,
шина событий — единственный канал в UI и Telegram, запись хранилища атомарная.
Главные риски — не в логике, а по краям: сеть без авторизации, merge в рабочей копии пользователя,
процессы claude без таймаута, секреты в окружении агента.

## Что чинить первым (порядок важен)
1. **Сеть.** Сервер открыт в Wi-Fi (`AO_HOST=0.0.0.0`) без входа: любой в сети может влить код в main,
   зарегистрировать любой путь на диске и запустить в нём pytest. Минимум — токен в заголовке/cookie для REST и WS.
2. **Merge не в рабочей копии.** `worktree.merge` делает `git checkout` в твоём основном чекауте и берёт
   «main» из текущей ветки. Любые незакоммиченные правки или чужая ветка → ложный «конфликт» и автоповтор.
   Мержить во временном worktree, base — из origin/HEAD или конфига.
3. **Таймаут и «Остановить».** `claude -p`, планировщик, pytest и after_merge-хук без таймаута; running-задачу
   нельзя убить из UI. Зависший процесс = мёртвый агент до рестарта.
4. **Секреты агенту.** `AO_TG_TOKEN` попадает в окружение claude, `.env` целевого репо симлинкуется в worktree,
   а `cat`/`python` разрешены. Чистить `AO_*` из env, `.env` линковать только по явному флагу.
5. **Побочные эффекты импорта.** `Office`/`TaskStore` создаются при импорте `app.main`, и `load()` переписывает
   tasks.json («running»→«failed»); окно .app импортирует main до проверки живого сервера. Переносить в lifespan.
6. **WS-реконнект.** Нет backoff и `loadState()` при переподключении; история 200 событий приходит как «живые» →
   дубли уведомлений и до 200 запросов `/api/state` подряд. `_broadcast` итерирует set во время `add`.
7. **auto_retry_at после рестарта** остаётся в tasks.json — карточка вечно обещает автоповтор, которого не будет.
8. **Дубли и цикл:** удаление задачи и after_merge продублированы в main.py и telegram.py, telegram импортирует main
   изнутри хендлера. Вынести в `Office`.
9. **Тесты по краям:** `ClaudeRunner.run` (stream-json, is_error, exit≠0), `worktree.merge` в грязном дереве,
   REST approve/reject/delete, команды Telegram — не покрыты; UI-тесты грепают строки, не поведение.
10. **Валидация:** `target` в `/api/tests/run` идёт в argv pytest; `/api/tests/runs/{id}` и скриншоты сценариев
    не проверяют, что репо зарегистрирован; `after_merge` — произвольный shell из файла без предупреждения.

## Мелочи
Мёртвый assert в test_office.py:71; ветка «done» в telegram.py никогда не уведомляет; `_safe_name` в двух модулях;
`on_event("startup")` deprecated; `MAX_AUTO_RETRIES` продублирована в JS; naive datetime без TZ и время в логе
без даты (ломается через полночь); rAF-цикл сцены крутится и на скрытой вкладке; кнопки-иконки без aria-label.

## Обновление: миссия «Надёжность» реализована и протестирована

Пункты 2, 3, 5, 6, 7, 8 из плана выше реализованы (ветки t1–t4, коммиты `b1ecd1f`,
`6746a8b`/`0207c50`, `77791f8`, `54dfa83`/`f7071fe`) и закрыты тестами:

- **п.2 (merge не в рабочей копии).** `worktree.merge` теперь мержит в отдельном временном
  `--detach` worktree, base продвигается через `git update-ref` — рабочая копия пользователя
  (незакоммиченные правки, untracked-файлы, любая выведенная ветка) не трогается. Настоящий
  конфликт классифицируется как `'conflict'` (заметка + автоповтор с `-prev`-подсказкой), прочая
  ошибка git (несуществующая база и т.п.) — как `'failed'`, без автоповтора. Тесты: real-git
  сценарии на грязной/чужой рабочей копии, реальный конфликт, ошибка мерджа без вызова
  `Office.retry` — `tests/test_worktree_merge_git.py`.
- **п.3 (таймаут и «Остановить»).** `ClaudeRunner.run`/`ClaudePlanner.plan` оборачивают подпроцесс
  в `asyncio.wait_for(config.AO_TASK_TIMEOUT / AO_PLAN_TIMEOUT)` и убивают всю process group по
  таймауту; `Office.stop()`/`POST /api/tasks/{id}/stop` отменяют running-задачу без автоповтора;
  `DELETE` на running сначала останавливает. Тесты: реальный зависший подпроцесс + дочерний
  процесс, таймаут и отмена — `tests/test_runner_timeout.py`; stop/DELETE — уже было в
  `tests/test_stop_and_lifecycle.py`, дозакрыто на уровне `Office.delete_task` (все статусы,
  включая todo/review/failed с отменой автоповтора) в `tests/test_office_delete_and_after_merge.py`.
- **п.5 (побочные эффекты импорта).** `Office`/`TaskStore` создаются в `lifespan`, не при импорте
  `app.main`; `tasks.json` не появляется до реального создания задачи. Тест:
  `tests/test_lifespan_and_auto_retry_restart.py`.
- **п.6 (WS-реконнект).** История 200 событий приходит одним `{kind:'history'}` и рендерится
  через `renderHistoryEvent` в `ui/app.js` — без `pushNotification`/`Floor.envelope`/
  `Floor.setState`/повторных `loadState()`; добавлен backoff и ping/pong на клиенте. Тест (node,
  реальные функции из `ui/app.js` через regex-экстракцию): `tests/test_ws_history_js.py`.
- **п.7 (auto_retry_at после рестарта).** `Office.resume_pending_auto_retries()` пересоздаёт
  таймер на оставшееся время (или сразу, если время уже прошло); битый `auto_retry_at` — чистит
  поле. Тесты: happy path уже был в `tests/test_stop_and_lifecycle.py`; битый timestamp и
  «далёкое будущее» (таймер не срабатывает раньше времени) — в
  `tests/test_lifespan_and_auto_retry_restart.py`.
- **п.8 (дубли delete_task/run_after_merge).** Обе операции — методы `Office`, а не дублированы в
  `main.py`/`telegram.py`. `run_after_merge` раньше не имел вообще ни одного теста (включая
  собственный таймаут 120с) — закрыто в `tests/test_office_delete_and_after_merge.py` (успех,
  ошибка, no-op без команды, таймаут с убийством process group).
