# Миссия: сводка Ральфа в Telegram — по запросу и автоматически каждые 20 минут

Записано 29.09.2026 по просьбе владельца: «выводить инфу через бота, когда идёт запрос и
автоматом через 20 минут».

## Что есть сейчас

- `app/core/digest.py::DigestScheduler` собирает факты (`collect_facts`) и текст Ральфа
  (`narrate`) каждые 15 минут для кнопки «Что происходит?» в офисе; кэш `workspace/digest.json`,
  событие `digest.ready`.
- `app/telegram.py`: команда `/digest` отдаёт кэш (может быть устаревшим), `/status` — список задач.
  Автоматической отправки сводки в Telegram нет.
- Блок «последний прогон test_hub» в фактах пустой: `_fetch_testhub_run` ходит на
  `/api/projects/{name}/runs` без сессии, test_hub отвечает 401. Имя проекта в test_hub теперь
  `VSHGU`, а репозиторий — `auto_tests_vshgu` (нужна карта repo → project).

## Что должно получиться

1. **По запросу**: `/digest` и обычное сообщение «что происходит?» (без учёта регистра и знаков)
   от админа собирают **свежую** сводку (`refresh_now()`), а не кэш; пока собирается — «Ральф
   думает…», потом текст. Если сводка не изменилась с прошлой отправки — так и написать одной
   строкой плюс время последнего изменения.
2. **Автоматически каждые 20 минут** (`AO_TG_DIGEST_MIN`, по умолчанию 20, 0 — выключено) бот
   шлёт сводку всем `AO_TG_ADMINS`. Если с прошлой отправки ничего не изменилось
   (`fingerprint` тот же) — не спамить: раз в час короткая строка «за час без изменений»,
   иначе молчать (`AO_TG_DIGEST_QUIET=1` по умолчанию; при `0` слать всегда). Первую сводку —
   через 20 минут после старта, не сразу.
3. **Формат сообщения**: заголовок с временем (24 ч), текст Ральфа, ниже 3–6 строк фактов:
   кто чем занят, что на проверке (с кнопками «Принять/Отклонить», как в карточке задачи),
   очередь, тихие репозитории свёрнуты одной строкой, последний прогон test_hub (статус,
   passed/failed, ссылка). Длина ≤ 3500 символов, лишнее обрезать с пометкой.
4. **Починить блок test_hub**: логиниться в test_hub служебной учёткой из `.env`
   (`AO_TESTHUB_LOGIN`/`AO_TESTHUB_PASSWORD`, по умолчанию `tg_bot`/`tg_bot` — она уже есть в
   test_hub) с кэшем cookie; карта репозиторий → проект test_hub (`AO_TESTHUB_PROJECTS`
   вида `auto_tests_vshgu=VSHGU`, по умолчанию имя папки). Ошибки test_hub — тихо, блока нет.
5. `.env.example`, README (раздел про бота), `python -m app.core.design_md lint` не ломать.

## Ограничения

- Тесты: планировщик (интервал, quiet-режим, первая отправка), команда/текстовый триггер,
  формат и обрезка, логин в test_hub на мок-сервере (401 → нет блока). Без реального Telegram
  и без реального test_hub в тестах. Существующие тесты проходят
  (`test_office_approve_on_failed_merge_does_not_retry_or_touch_branch` — известный красный на
  main, не чинить в этой миссии).
- Коммиты небольшие, на русском. После слияния — перезапуск сервера офиса владельцем.
