# Миссия: кнопка «Что происходит?» и новый персонаж Оскар

Записано 25.09.2026 по просьбе владельца. Аналог вопроса «что сейчас происходит?», который
владелец задаёт ассистенту: кнопка в шапке офиса, раз в 15 минут она начинает светиться
неоном, по нажатию — модалка с текущим состоянием проектов. Сводку составляет новый персонаж
**Оскар · сводки и цифры** (бухгалтер из «Офиса»: точный, сухой, любит числа).

## Принципы

- **Факты считает код, а не модель.** Все цифры и списки в модалке собираются детерминированно
  из `office.store` (задачи, миссии), `roster`, `paused_repos`, событий `bus`, и, если доступен,
  test_hub (`GET http://127.0.0.1:8700/api/projects/<name>/runs` — последний прогон, только чтение,
  таймаут 2 с, при недоступности блок скрывается).
- **Оскар пишет только текст.** 3–5 предложений на русском, в характере, поверх готовых фактов.
  Один вызов `claude -p` с моделью `haiku` (переопределяется `AO_DIGEST_MODEL`), без инструментов,
  таймаут 60 с. Вызов делается **только если с прошлой сводки что-то изменилось** (есть новые
  события задач/миссий); иначе сводка не пересобирается и кнопка не светится.
- **Дёшево и безопасно.** Никаких секретов в промпте, только публичные поля задач (title,
  status, agent, error[:200]). При ошибке вызова — модалка показывает факты без текста Оскара,
  с пометкой «Оскар молчит: <причина>».
- Режим `FAKE` (тесты, `AO_FAKE=1`): текст Оскара — заглушка без вызова claude.

## Бэкенд

1. `app/core/digest.py`:
   - `collect_facts(store, roster, paused, testhub=True) -> dict`: по каждому репозиторию —
     активные миссии (название, сделано/всего задач, кто работает), задачи `running`/`review`/
     `todo`, задачи `failed` за последние 24 ч с причиной, паузы, агенты и их состояние,
     последний прогон test_hub (id, стенд, passed/failed, время); плюс «с прошлой сводки»:
     сколько задач сдано/принято/упало, стоимость по API за сутки (`build_summary`).
   - `narrate(facts) -> str`: промпт Оскара + факты → текст; кэш в `workspace/digest.json`
     (`generated_at`, `facts`, `text`, `changed`).
   - `DigestScheduler`: asyncio-таймер каждые `AO_DIGEST_INTERVAL_MIN` (по умолчанию 15) минут;
     сравнивает отпечаток фактов с прошлым; при изменении собирает сводку и шлёт событие
     `digest.ready` в `bus` (фронт зажигает кнопку). Стартует в lifespan приложения.
2. API в `app/main.py`:
   - `GET /api/digest` — текущая сводка из кэша (`facts`, `text`, `generated_at`, `fresh`).
   - `POST /api/digest/refresh` — принудительно пересобрать (для кнопки «обновить» в модалке).
   - `POST /api/digest/seen` — владелец посмотрел: `fresh=false`, кнопка гаснет.
3. Персонаж: в `DEFAULT_ROSTER` (`app/core/roster.py`) добавить
   `{"name": "oscar", "title": "Оскар · сводки и цифры", "desk": 3, "color": "#39ff88",
   "avatar": "", "system": "<характер>"}`. Оскар **не берёт задачи из очереди**: в
   `Office._dispatch`/выборе агента для todo он исключается (поле роли `reporter: true` или
   список `NON_WORKER_AGENTS`). Существующий `roster.json` в workspace без Оскара должен
   получить его при загрузке (миграция: если персонажа нет — добавить).
4. Telegram (`app/tg_bot.py` или где живёт бот офиса): команда `/digest` возвращает ту же
   сводку текстом; при `digest.ready` — ничего не слать (владелец сам спросит), чтобы не шуметь.

## Фронтенд (`ui/`)

1. Кнопка в `<header>` рядом с колокольчиком: `#btn-digest`, подпись «Что происходит?»,
   у Оскара свой цвет `#39ff88`. Состояния: обычная; `fresh` — неоновое свечение
   (box-shadow/text-shadow в цвете Оскара, мягкая пульсация 2 с, `prefers-reduced-motion`
   → без пульсации, только статичное свечение). Зажигается по событию `digest.ready` из `/ws`
   и при загрузке страницы, если `GET /api/digest` вернул `fresh=true`. Гаснет после
   открытия модалки (`POST /api/digest/seen`).
2. Модалка `#dlg-digest` (как `#dlg-notify`, `<dialog>`): шапка с портретом/спрайтом Оскара
   и временем сводки; блок «Оскар говорит» с текстом (печатается через `typeSpeech`, как
   реплики агентов); ниже факты по репозиториям: миссии с прогресс-баром «сделано/всего»,
   кто чем занят, задачи на ревью (ссылки открывают карточку задачи), упавшие за сутки с
   причиной, паузы, последний прогон test_hub; итог «с прошлой сводки». Кнопки «Обновить»
   (`POST /api/digest/refresh`, спиннер) и «Понятно». Мобильная вёрстка ≤768px — как у
   остальных диалогов.
3. Офис (`ui/floor.js`): четвёртый стол для Оскара, спрайт без портрета (как сейчас для
   агентов без avatar); когда сводка собирается — состояние `working`, реплика над головой
   «Считаю…»; при `digest.ready` — реплика «Сводка готова».
4. Все три темы (Аркада, Game Boy, Кибер) — свечение читаемо в каждой.

## Тесты (`tests/`)

- `collect_facts` на фикстурном store: миссия с 2/5 задачами, задача в review, упавшая
  за сутки, пауза репозитория — все попадают в факты; test_hub недоступен → блок отсутствует.
- Планировщик: без изменений фактов не вызывает `narrate` и не шлёт `digest.ready`;
  с изменениями — вызывает один раз и шлёт событие (spawner claude замокан, см. память
  о зависании pytest-asyncio при реальном subprocess).
- API: `/api/digest`, `/refresh`, `/seen` — коды и поля; `seen` гасит `fresh`.
- Roster: миграция добавляет Оскара; Оскар не получает todo-задачи при диспетчеризации.
- Существующие тесты проходят.

## Ограничения

- Не менять логику запуска задач, ретраев и мерджа, кроме исключения Оскара из очереди.
- Никаких новых зависимостей в `requirements.txt`, кроме уже используемых.
- После слияния офис нужно перезапустить — это делает владелец/ассистент, не агент.

## Приёмка

- Через 15 минут после изменений в задачах кнопка светится; клик открывает модалку с
  текстом Оскара и фактами; после закрытия свечение гаснет; без изменений — не светится.
- `/digest` в Telegram отдаёт ту же сводку.
- Оскар виден в офисе за четвёртым столом и не появляется как исполнитель ни в одной задаче.
